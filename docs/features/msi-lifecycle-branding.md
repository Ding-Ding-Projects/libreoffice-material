# Windows Installer lifecycle branding

## Behavior

The Windows MSI now bundles deterministic Material artwork for its standard
banner, welcome/completion side image, and wide branding variant. The generator
reads the project's own light Material palette and draws the bitmaps locally;
it uses no downloaded assets, fonts, analytics, or third-party services.

The contract follows the artwork through fourteen real Windows Installer
stages: install welcome, setup type, customer information, license, file
associations, ready/install progress/success, maintenance welcome/type/remove,
patch welcome, error, and interruption. Cancel Setup, Files in Use, and Restart
Manager Files in Use retain their native safe defaults and cancellation paths.

Windows Installer continues to own the window frame, caption buttons, system
controls, DPI behavior, keyboard operation, and accessibility semantics. The
project supplies compatible branding and the existing Segoe UI hierarchy; it
does not replace or fake installer dialogs.

## Configuration

Run the deterministic generator from the repository root:

```sh
python bin/generate-material-msi-branding.py
python bin/generate-material-msi-branding.py --check
```

The checked-in 24-bit BMP files keep the dimensions expected by the MSI tables:
632×57 (`Banner.bmp`), 162×312 (`Image.bmp`), and 493×312 (`Image_2.bmp`).
`CustomTarget_install.mk` copies the bundled assets into each generated MSI
template; `Binary.idt` binds `BannerBmp` and `ImageBmp` to the live controls.

## Failure modes

- A token, generated byte, SHA-256, bitmap header, bit depth, or expected
  dimension change fails the source contract.
- A missing or renamed Binary/Control/Dialog table mapping fails closed.
- A default or cancel action change in a lifecycle or decision dialog fails.
- If generation cannot resolve the local Material palette, it writes no
  substitute network image and reports the exact missing role.
- Branding conformance does not prove installation, repair, major upgrade,
  uninstall, restart suppression, rollback, or reboot behavior.

## Security and accessibility

The artwork is decorative and contains no executable payload or remote
resource. Destructive and restart-related choices remain native decisions with
their existing safe defaults. Explicit text colors are not forced, so Windows
Installer and the operating system retain control of high-contrast text and
control rendering.

## Verification

`qa/windows-ui-contract/msi-lifecycle-composition.json` is enforced by the
generator check, `bin/check-msi-lifecycle-composition.py`, and ten mutations.
It pins all assets, token roles, table mappings, typography, fourteen lifecycle
dialogs, three decision dialogs, template copying, and the existing lifecycle
harness entry points. Immutable source commit
`3d25fea0279d9f44bc7daff7a2b329509d38f951` carries that implementation and its
native-shell ledger credit. `runtime_verified` remains `false`: a built MSI
must still complete the real lifecycle harness before install behavior is
claimed. That review-first host now obtains its byte-pinned assets through
`gh release download` and launches Windows Sandbox only through a run-scoped
Lowlevel MCP off-screen desktop. The static validator rejects raw HTTP clients,
visible-session launch, missing normal-disposal checks, or an unreleased desktop
handle; this transport hardening is not itself a lifecycle result.
